## 1. Overview & Architectural Principles

The S1 Inventory Foundation provides an append-only signed inventory ledger with immutable transaction facts, audit integration, and atomic idempotency replay.

1. **Zero Client Direct Table Writes:** All 17 inventory tables have Row Level Security enabled. Only `SELECT` is granted to authenticated users matching active Admin or Staff roles. Direct `INSERT`, `UPDATE`, or `DELETE` commands are revoked from `public`, `anon`, and `authenticated`.
2. **Strict Dispatcher Boundary:** All business state mutations must be dispatched via `public.inventory_command(p_operation, p_payload, p_retry_key)`.
3. **Snapshot Consistency & Read Models:** All queries and paginated list views run through `public.inventory_read(p_resource, p_filters)`.
4. **Canonical Decimals:** All quantities, conversion factors, and currency amounts are passed and returned as exact canonical decimal strings (`numeric(18,6)` for stock and factor, `numeric(20,4)` for unit cost). No JavaScript floating-point conversions.
5. **Physical Truth & Fact Immutability:** Posted intake documents (`inventory_receipts`, `inventory_opening_batches`), origins (`inventory_stock_origins`), facts (`inventory_stock_facts`), transactions (`inventory_transactions`), and ledger lines (`inventory_transaction_lines`) are immutable. Triggers physically block accidental updates or deletes. Corrections append new fact versions and post server-calculated signed deltas.
6. **Writer serialization:** A transaction-scoped advisory lock serializes S1 commands before business/revision checks. This favors deterministic integrity over write throughput; reads remain concurrent.

## 2. Public Database Interface

### 2.1 `public.inventory_command`

Executes a named, typed inventory business command with atomic replay caching, revision checking, and advisory locking.

```sql
public.inventory_command(
  p_operation text,
  p_payload jsonb,
  p_retry_key uuid
) returns jsonb
```

#### Parameters:

- `p_operation`: Required operation name (see allowlist below).
- `p_payload`: JSONB payload containing command inputs.
- `p_retry_key`: UUID generated by the client representing the request intent. Replays with identical `(actor_id, p_operation, p_retry_key)` and identical payload return the previously committed result without re-executing. Replays with changed payload raise `RETRY_PAYLOAD_MISMATCH`.

#### Returns:

A JSONB object with primary result IDs (e.g. `{ "id": "...", "revision": 1 }` or `{ "transaction_id": "...", "receipt_id": "..." }`).

---

### 2.2 `public.inventory_read`

Provides paginated, filtered, snapshot-consistent read access across all Inventory entities.

```sql
public.inventory_read(
  p_resource text,
  p_filters jsonb default '{}'::jsonb
) returns jsonb
```

#### Parameters:

- `p_resource`: Resource name allowlist:
  - `items`
  - `categories`
  - `uoms`
  - `suppliers`
  - `locations`
  - `sources`
  - `source_lines`
  - `balances`
  - `transactions`
  - `cohorts`
  - `transaction_detail`
- `p_filters`: JSONB object with optional filter keys:
  - `q`: Search string (code, name, reference)
  - `id`: Target UUID
  - `item_id`: Target catalog item UUID
  - `location_id`: Target storage location UUID
  - `source_id`: Target acquisition record UUID
  - `origin_id`: Target stock origin UUID
  - `condition`: `'good'` or `'damaged'`
  - `active`: Boolean filter
  - `page`: 1-based page index (default `1`)
  - `page_size`: Bounded integer, 1 to 100 (default `20`)

#### Returns:

```json
{
  "rows": [...],
  "total": 42,
  "page": 1,
  "page_size": 20
}
```

## 4. Operation Payloads and Validation Rules

### 4.1 Master Operations

#### `create_inventory_item`

- **Actor:** Admin, Staff
- **Payload:**
  ```json
  {
    "code": "GLOVE-NITRILE-M",
    "name": "Nitrile Gloves Size M",
    "category_id": "uuid",
    "material_kind": "chemical | other",
    "base_uom_code": "box",
    "tracking_strategy": "quantity | serialized",
    "return_semantics": "returnable | nonreturnable | in_place",
    "expiry_required": true
  }
  ```
- **Rules:**
  - `code` is trimmed and uppercased; unique across all items.
  - `material_kind = 'chemical'` strictly requires `expiry_required = true`.
  - Initial `active = true`, `revision = 1`.
- **Returns:** `{ "id": "uuid", "revision": 1 }`

#### `update_inventory_item`

- **Actor:** Admin, Staff
- **Payload:**
  ```json
  {
    "id": "uuid",
    "expected_revision": 1,
    "name": "Nitrile Gloves Size M (Blue)",
    "category_id": "uuid",
    "material_kind": "other",
    "base_uom_code": "box",
    "tracking_strategy": "quantity",
    "return_semantics": "nonreturnable",
    "expiry_required": false
  }
  ```
- **Rules:**
  - `expected_revision` must match current item revision.
  - **Sensitive Axes Lock:** If any stock fact has been recorded for this item (`exists (select 1 from inventory_stock_origins where catalog_item_id = id)`), attempts to change `base_uom_code`, `material_kind`, `tracking_strategy`, `return_semantics`, or `expiry_required` are rejected with `SENSITIVE_AXES_LOCKED`.
- **Returns:** `{ "id": "uuid", "revision": 2 }`

#### `inactivate_inventory_item` / `reactivate_inventory_item`

- **Actor:** Admin only (INV-019)
- **Payload:**
  ```json
  {
    "id": "uuid",
    "expected_revision": 1,
    "reason": "Manufacturer discontinued line"
  }
  ```
- **Rules:** Non-blank `reason` is required. Revision increments.
- **Returns:** `{ "id": "uuid", "revision": 2 }`

### 4.3 Physical Stock Operations

#### `receive_stock`

- **Actor:** Admin, Staff
- **Payload:**
  ```json
  {
    "receipt_reference": "RCV-2026-10-03-01",
    "occurred_at": "2026-10-03T10:00:00Z",
    "reason": "Physical delivery at warehouse gate",
    "lines": [
      {
        "line_key": "L1",
        "source_line_id": "uuid",
        "catalog_item_id": "uuid",
        "location_id": "uuid",
        "purchase_quantity": "10.000000",
        "purchase_uom_code": "box",
        "conversion_factor": "50.000000",
        "good_quantity": "500.000000",
        "damaged_quantity": "0.000000",
        "expiry_precision": "day",
        "expiry_input": "2027-08-15",
        "evidence_note": "Carton seal intact"
      }
    ]
  }
  ```
- **Rules:**
  - `receipt_reference` must be unique across all receipts (prevents double posting under a new retry key).
  - `source_line_id` is mandatory for normal receipts.
  - `purchase_quantity > 0` and `conversion_factor > 0`.
  - Exact multiplication: `base_quantity = purchase_quantity * conversion_factor`.
  - Conservation equation: `good_quantity + damaged_quantity = base_quantity`.
  - Expiry precision:
    - If `material_kind = 'chemical'` or `expiry_required = true`: must be `'day'` or `'month'`. Cannot be `'not_required'` or `'unknown'`.
    - Month precision (`YYYY-MM`) normalizes to the exact last day of that calendar month (accounting for leap years, e.g. `2028-02` -> `2028-02-29`).
  - Serialized items are rejected in S1 quantity receive.
- **Returns:** `{ "transaction_id": "uuid", "receipt_id": "uuid" }`

#### `confirm_opening_balance`

- **Actor:** Admin only (INV-037)
- **Payload:**
  ```json
  {
    "cutover_key": "CUTOVER-2026-PHASE1",
    "count_cutoff": "2026-10-01T00:00:00Z",
    "scope_description": "Lab Chemistry Room 101 initial physical count",
    "provenance_note": "Audited by Dean and Lab Specialist",
    "synthetic": true,
    "lines": [
      {
        "line_key": "ROW-1",
        "provenance_group": "group-chem-1",
        "catalog_item_id": "uuid",
        "location_id": "uuid",
        "good_quantity": "250.000000",
        "damaged_quantity": "0.000000",
        "expiry_precision": "unknown",
        "expiry_input": null,
        "evidence_note": "Legacy label faded"
      }
    ]
  }
  ```
- **Rules:**
  - `synthetic` must be explicitly `true`.
  - `cutover_key` unique.
  - Opening scope exclusion: Each `(catalog_item_id, location_id)` can be claimed by only one opening batch.
  - `'unknown'` expiry precision is permitted **only** during opening balance confirmation.
  - Purchase fields are stored as `null`.
- **Returns:** `{ "transaction_id": "uuid", "opening_batch_id": "uuid" }`

#### `correct_receipt`

- **Actor:** Admin, Staff + mandatory reason (INV-018)
- **Payload:**
  ```json
  {
    "transaction_id": "uuid",
    "reason": "Correcting receiving count typo: 10 boxes instead of 100",
    "lines": [
      {
        "origin_id": "uuid",
        "expected_version": 0,
        "location_id": "uuid",
        "purchase_quantity": "10.000000",
        "purchase_uom_code": "box",
        "conversion_factor": "50.000000",
        "good_quantity": "500.000000",
        "damaged_quantity": "0.000000",
        "expiry_precision": "day",
        "expiry_input": "2027-08-15",
        "evidence_note": "Verified with physical count in cabinet A"
      }
    ]
  }
  ```
- **Rules:**
  - Creates transaction `CORRECT_RECEIPT` referencing the original transaction.
  - Appends new fact version (`version = expected_version + 1`).
  - Calculates and inserts signed delta ledger lines (`inventory_transaction_lines`).
  - Balances update atomically. Rejects if balance would become negative (`INSUFFICIENT_ORIGIN_STOCK`).
  - Downstream guard: rejects if affected origin has movements outside its correction chain (`DEPENDENT_FACT`).
- **Returns:** `{ "transaction_id": "uuid" }`

#### `reverse_receipt`

- **Actor:** Admin, Staff + mandatory reason
- **Payload:**
  ```json
  {
    "transaction_id": "uuid",
    "reason": "Invoice cancelled; entire shipment rejected at dock",
    "versions": [
      {
        "origin_id": "uuid",
        "expected_version": 0
      }
    ]
  }
  ```
- **Rules:**
  - Sets target purchase/base/good/damaged quantities to `0` while retaining prior purchase UOM and factor.
  - Debits all remaining cohort balances to zero.
  - Terminal operation for the origin.
- **Returns:** `{ "transaction_id": "uuid" }`

#### `correct_opening_balance`

- **Actor:** Admin only
- **Rules:**
  - Same correction engine as `correct_receipt`, targeting an `OPENING` transaction.
  - If destination location changes, atomically claims the new destination in `inventory_opening_scope` (verifying no collision with another batch) and retains the old claim.
- **Returns:** `{ "transaction_id": "uuid" }`

#### `verify_opening_expiry`

- **Actor:** Admin only
- **Payload:**
  ```json
  {
    "origin_id": "uuid",
    "expected_version": 0,
    "expiry_precision": "month",
    "expiry_input": "2027-12",
    "evidence_note": "Certificate of Analysis retrieved from supplier archive",
    "reason": "Resolved unknown expiry status"
  }
  ```
- **Rules:**
  - Current fact must have `expiry_precision = 'unknown'`.
  - New fact version created with known expiry date.
  - **Zero Stock Delta:** Ledger lines are not created; balances are unchanged.
- **Returns:** `{ "transaction_id": "uuid", "fact_id": "uuid" }`

  "item_name": "Nitrile Gloves Size M",
  "base_uom_code": "box",
  "base_uom_name": "Box",
  "location_id": "uuid",
  "location_code": "WH-A1",

  "quantity": "500.000000",
  "eligible_quantity": "500.000000",

## 6. Standard Error Codes

All errors raised by `inventory_command` or `inventory_read` use standard PostgreSQL error codes and explicit exception prefixes:

| Error Prefix                        | PostgreSQL Code | Description                                                                              |
| ----------------------------------- | --------------- | ---------------------------------------------------------------------------------------- |
| `AUTH_DENIED`                       | `42501`         | User is unauthenticated, inactive, or lacks required Admin/Staff role                    |
| `TABLE_IMMUTABLE`                   | `42501`         | Attempted direct UPDATE or DELETE on immutable ledger/history table                      |
| `SENSITIVE_AXES_LOCKED`             | `42501`         | Attempted to change core attributes of catalog item after stock facts exist              |
| `DEPENDENT_FACT`                    | `42501`         | Origin has subsequent stock movements blocking correction/reversal                       |
| `STALE_REVISION`                    | `23505`         | Expected entity revision or fact version does not match database state                   |
| `BUSINESS_DUPLICATE`                | `23505`         | Receipt reference or opening cutover key has already been posted                         |
| `RETRY_PAYLOAD_MISMATCH`            | `23505`         | Retry key was already executed with different payload parameters                         |
| `OPENING_SCOPE_CONFLICT`            | `23505`         | Catalog item at location is already claimed by another opening batch                     |
| `CYCLIC_LOCATION_DETECTED`          | `23514`         | Location hierarchy would form a loop or self-parent                                      |
| `INVALID_DECIMAL`                   | `22023`         | Non-canonical decimal string, scale limit violation, or sum mismatch                     |
| `INVALID_EXPIRY`                    | `22023`         | Missing required chemical expiry, unknown precision in receipt, or invalid calendar date |
| `INSUFFICIENT_ORIGIN_STOCK`         | `22023`         | Correction delta would cause balance to drop below zero                                  |
| `INACTIVE_REFERENCE`                | `22023`         | Referenced category, UOM, supplier, item, or location is inactive                        |
| `ITEM_NOT_FOUND` / `LINE_NOT_FOUND` | `P0002`         | Referenced entity ID does not exist                                                      |
